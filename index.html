6.1 从需求到页面骨架

信息架构与视觉层级：先决定放什么，再决定怎么放。

6.1 From Requirements to Page Structure

Information architecture and visual hierarchy: decide what to show before deciding how to place it.

案例问题

我们已经有导航、筛选器、4 个 KPI、趋势图、占比图和区域数据。第一步不是写 CSS，而是判断这些信息之间的关系。

思考：用户打开页面后的前 3 秒最应该看到什么？哪些内容属于概览，哪些属于进一步分析？

理论：信息架构与视觉层级

Dashboard 可以组织为 导航层 → 概览层 → 分析层 → 细节层。布局首先是信息组织问题，其次才是 CSS 问题。

任务优先

先明确用户进入页面最需要完成的任务。

阅读顺序

核心信息应位于自然的视觉起点。

主次层级

概览、主要分析和辅助内容不应拥有相同视觉权重。

案例决策：KPI 承担快速概览任务，因此放在分析图表之前；主要趋势比辅助占比拥有更高的信息优先级。

Case Problem

We already have navigation, filters, four KPIs, a trend chart, a share chart, and regional data. The first step is not writing CSS; it is understanding the relationships among these pieces of information.

Think: What should users see in the first three seconds? Which content belongs to the overview, and which belongs to deeper analysis?

Theory: Information Architecture & Visual Hierarchy

A dashboard can be organized into navigation → overview → analysis → detail. Layout is first an information-organization problem and only then a CSS problem.

Task Priority

Identify the most important task users need to complete.

Reading Order

Core information should appear at the natural visual starting point.

Hierarchy

Overview, primary analysis, and supporting content should not have equal visual weight.

Case decision: KPIs provide a rapid overview, so they appear before analytical charts; the primary trend has higher information priority than the supporting share chart.

关键代码

Key Code

<header class="dashboard-header">...</header>
<div class="dashboard-shell">
  <aside class="sidebar">...</aside>
  <main>
    <section class="kpi-area">...</section>
    <section class="analysis-area">...</section>
  </main>
</div>

HTML 先表达导航、概览和分析的语义关系，CSS 再把这套结构视觉化。

<header class="dashboard-header">...</header>
<div class="dashboard-shell">
  <aside class="sidebar">...</aside>
  <main>
    <section class="kpi-area">...</section>
    <section class="analysis-area">...</section>
  </main>
</div>

HTML first expresses the semantic relationship between navigation, overview, and analysis; CSS then visualizes that structure.

6.2 建立页面空间系统

对齐、邻近、重复与留白：为什么元素都放对了，页面还是不好看？

6.2 Building a Page Spacing System

Alignment, proximity, repetition, and white space: why can a correct structure still look poor?

案例问题

页面骨架已经正确，但标题、数字、卡片和图表彼此拥挤。原因不是少写了某个 CSS 属性，而是没有统一的空间规则。

理论：空间设计原则

Alignment 对齐

共享视觉基准线，减少随机感。

Proximity 邻近

同组信息靠近，不同组之间增加距离。

Repetition 重复

同类组件重复相同尺寸、间距和样式规则。

White Space 留白

空白帮助分组并建立视觉呼吸感。

Box Model 盒模型

padding 管内部空间，gap/margin 管组件间空间。

Spacing System 间距系统

使用 4、8、16、24 等统一尺度，而不是随意设置距离。

案例决策：KPI 内部使用较小间距，卡片之间统一使用 16px，KPI 区和图表区使用更大的间距表达不同信息组。

Case Problem

The page structure is correct, but titles, numbers, cards, and charts feel crowded. The problem is not a missing CSS property; it is the absence of a consistent spacing system.

Theory: Spatial Design Principles

Alignment

Use shared visual baselines to reduce randomness.

Proximity

Keep related information close and increase distance between different groups.

Repetition

Repeat the same sizing, spacing, and styling rules for similar components.

White Space

Empty space supports grouping and creates visual breathing room.

Box Model

Padding controls internal space; gap and margin separate components.

Spacing System

Use a consistent scale such as 4, 8, 16, and 24 instead of arbitrary distances.

Case decision: Use smaller spacing inside KPIs, a consistent 16px gap between cards, and a larger gap between the KPI group and chart group.

关键代码

Key Code

* { box-sizing: border-box; }
.dashboard-main { padding: 24px; }
.kpi-grid { gap: 16px; }
.kpi-card { padding: 20px; }
.analysis-area { margin-top: 24px; }

重点不是背下 16px 或 24px，而是让同一级别的空间关系保持一致。

* { box-sizing: border-box; }
.dashboard-main { padding: 24px; }
.kpi-grid { gap: 16px; }
.kpi-card { padding: 20px; }
.analysis-area { margin-top: 24px; }

The goal is not to memorize 16px or 24px; it is to keep spacing relationships consistent at the same hierarchy level.

6.3 构建 Dashboard 网格

网格系统与 CSS Grid：用稳定比例表达内容权重。

6.3 Building the Dashboard Grid

Grid systems and CSS Grid: use stable proportions to express information weight.

案例问题

趋势图承担更重要的时间变化分析，占比图属于辅助分析，因此两个图表不一定应该机械地各占 50%。

不推荐：给图表随意设置 713px、327px 等孤立宽度。页面尺寸改变后，这些数字很难维护。

理论：12 栏网格系统

将内容区抽象成 12 个等宽列，可以自然表达 1/2、1/3、2/3、1/4 等常见比例。网格系统建立的是一套可以重复使用的空间规则。

123456789101112
案例决策：趋势图占 8 栏，占比图占 4 栏，区域分析占完整 12 栏。空间比例由任务优先级决定。

Case Problem

The trend chart supports the more important time-based analysis, while the share chart is supporting analysis. Therefore, a mechanical 50/50 split is not always appropriate.

Not recommended: Assign isolated widths such as 713px and 327px. These arbitrary values become difficult to maintain when the page size changes.

Theory: The 12-Column Grid System

Dividing the content area into 12 equal columns naturally supports common proportions such as 1/2, 1/3, 2/3, and 1/4. A grid system creates reusable spatial rules.

123456789101112
Case decision: The trend chart spans 8 columns, the share chart spans 4, and regional analysis spans all 12. Spatial proportion is determined by task priority.

关键代码

Key Code

.analysis-grid {
  display: grid;
  grid-template-columns: repeat(12, 1fr);
  gap: 20px;
}
.trend-chart { grid-column: span 8; }
.share-chart { grid-column: span 4; }
.region-chart { grid-column: span 12; }

Grid 语法负责实现比例，而“为什么是 8:4”来自内容的重要程度。

.analysis-grid {
  display: grid;
  grid-template-columns: repeat(12, 1fr);
  gap: 20px;
}
.trend-chart { grid-column: span 8; }
.share-chart { grid-column: span 4; }
.region-chart { grid-column: span 12; }

Grid syntax implements the proportion, while the reason for choosing 8:4 comes from the importance of the content.

6.4 布局内部组件

一致性、分组与 Flex：Grid 管大结构，Flex 管小组件。

6.4 Laying Out Components

Consistency, grouping, and Flexbox: Grid for structure, Flexbox for components.

案例问题

Grid 已经解决了四张 KPI 卡片如何排列，但每张卡片内部还有标题、趋势标签和核心数字。这是一维排列问题。

理论：一致性、分组与对齐

Consistency 一致性

同类 KPI 使用相同标题位置、字号和内边距。

Grouping 分组

标题和趋势标签属于头部组，核心数字属于主要信息层。

Alignment 对齐

标题左对齐、趋势右对齐，形成稳定扫描路径。

技术选择：当问题是“整个页面有几行几列”时优先考虑 Grid；当问题是“一行中的元素如何分布”时优先考虑 Flex。

Case Problem

Grid already determines how four KPI cards are arranged, but each card still contains a title, trend badge, and primary number. This is a one-dimensional layout problem.

Theory: Consistency, Grouping & Alignment

Consistency

Similar KPIs use the same title position, type scale, and padding.

Grouping

The title and trend badge form a header group, while the primary number forms the main information level.

Alignment

Left-align the title and right-align the trend to create a stable scanning path.

Technology choice: Prefer Grid when the problem concerns rows and columns across the page; prefer Flexbox when arranging elements along one axis inside a component.

关键代码

Key Code

.kpi-header {
  display: flex;
  justify-content: space-between;
  align-items: center;
}
.kpi-value {
  margin-top: 14px;
  font-size: 30px;
}

Flex 的重点不是背属性，而是先判断主轴，再决定元素在主轴上的分布方式。

.kpi-header {
  display: flex;
  justify-content: space-between;
  align-items: center;
}
.kpi-value {
  margin-top: 14px;
  font-size: 30px;
}

The key to Flexbox is not memorizing properties. First identify the main axis, then decide how elements should be distributed along it.

6.5 建立可视化信息层级

格式塔原则与内容权重：页面不是“排整齐”就结束了。

6.5 Building Visual Hierarchy

Gestalt principles and information weight: a good layout is more than neat alignment.

案例问题

即使所有模块已经对齐，如果每个模块面积、样式和强调程度都一样，用户仍然需要自己寻找重点。

理论：格式塔原则

用户通常先感知整体结构，再读取细节。布局可以利用人的视觉组织规律降低理解成本。

Proximity 邻近性

靠近的元素容易被理解为同一组。

Similarity 相似性

相似样式暗示相同功能或层级。

Common Region 共同区域

同一卡片边界强化信息归属。

Hierarchy 视觉层级

重要内容获得更大的面积、位置或字号。

White Space 留白

空间可以自然分隔不同信息组。

Consistency 一致性

重复规则降低理解成本，让异常更容易被发现。

案例决策：主要趋势图获得更大面积；同类 KPI 保持相似；辅助内容降低视觉权重。

Case Problem

Even when every module is aligned, users still have to search for the important content if all modules have the same size, style, and emphasis.

Theory: Gestalt Principles

Users usually perceive the overall structure before reading details. Layout can use human perceptual organization to reduce cognitive effort.

Proximity

Nearby elements are likely to be perceived as one group.

Similarity

Similar appearance suggests similar function or hierarchy.

Common Region

A shared card boundary strengthens perceived grouping.

Visual Hierarchy

Important content receives more area, stronger placement, or larger type.

White Space

Space can naturally separate different information groups.

Consistency

Repeated rules reduce cognitive effort and make exceptions easier to notice.

Case decision: Give the primary trend more area, keep similar KPIs visually consistent, and reduce the visual weight of supporting content.

关键代码

Key Code

.primary-chart { grid-column: span 8; }
.secondary-chart { grid-column: span 4; }
.detail-chart { grid-column: span 12; }

代码只是实现手段。真正的设计决策是：为什么 primary chart 值得占 8 栏？答案来自任务优先级和视觉层级。

.primary-chart { grid-column: span 8; }
.secondary-chart { grid-column: span 4; }
.detail-chart { grid-column: span 12; }

Code is only the implementation. The real design decision is why the primary chart deserves eight columns; the answer comes from task priority and visual hierarchy.

6.6 从桌面到移动端

内容优先级与响应式设计：不是缩小页面，而是重新组织信息。

6.6 From Desktop to Mobile

Content priority and responsive design: reorganize information instead of merely shrinking the page.

案例问题

手机屏幕无法容纳完整桌面 Dashboard。如果只是把所有东西缩小，文字和图表会难以阅读。

关键观念：Responsive Design ≠ Desktop × 0.5。响应式设计意味着根据空间和任务重新组织内容。

理论：内容优先级与渐进披露

Content Priority 内容优先级

核心 KPI 和主要趋势优先出现。

Progressive Disclosure 渐进披露

先展示必要信息，需要时再提供更多细节。

Breakpoints 断点

断点服务于内容重排，而不是机械对应某个设备型号。

案例决策：移动端隐藏固定侧栏，KPI 改为两列，图表改为单列，并暂时隐藏低优先级的详细区域。

Case Problem

A mobile screen cannot contain the complete desktop dashboard. Simply shrinking everything would make text and charts difficult to read.

Key idea: Responsive Design ≠ Desktop × 0.5. Responsive design means reorganizing content according to available space and user tasks.

Theory: Content Priority & Progressive Disclosure

Content Priority

Core KPIs and the primary trend appear first.

Progressive Disclosure

Show essential information first and reveal more detail when needed.

Breakpoints

Breakpoints should support content reflow rather than mechanically target a device model.

Case decision: On mobile, hide the fixed sidebar, arrange KPIs in two columns, stack charts vertically, and temporarily hide low-priority detail areas.

关键代码

Key Code

@media (max-width: 768px) {
  .dashboard-shell { grid-template-columns: 1fr; }
  .sidebar { display: none; }
  .kpi-grid { grid-template-columns: repeat(2, 1fr); }
  .analysis-grid { grid-template-columns: 1fr; }
  .detail-area { display: none; }
}

媒体查询只是实现工具，真正的核心是“哪些内容在小屏幕上仍然最重要”。

@media (max-width: 768px) {
  .dashboard-shell { grid-template-columns: 1fr; }
  .sidebar { display: none; }
  .kpi-grid { grid-template-columns: repeat(2, 1fr); }
  .analysis-grid { grid-template-columns: 1fr; }
  .detail-area { display: none; }
}

Media queries are only an implementation tool. The real question is which content remains most important on a small screen.
